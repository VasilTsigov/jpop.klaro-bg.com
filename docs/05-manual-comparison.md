# Етап 5 – ръчно сравнение със стария сайт (чеклист)

Как се работи: два прозореца един до друг – **стар сайт** (живият) и **нов** (`php artisan serve` в WSL, http://localhost:8000; писмата в dev отиват в `storage/logs/laravel.log` или Mailpit). За всеки ред: `[ ]` не е проверено, `[x]` съвпада, `[~]` разлика – приета (вписва се в таблицата „Разлики“), `[!]` разлика – за поправяне.

Правило: **първо 1:1**. Разлика, която не е в списъка „Приети отклонения“, е дефект.

## 0. Подготовка
- [ ] Тестови акаунти и в двете системи: автор А, автор Б, рецензент Р1, Р2, Р3, редактор Е1, втори редактор Е2 (за „редактор подава – друг обработва“).
- [ ] На стария сайт – тестови ръкопис, който после се изтрива/отхвърля; не се пипат реални ръкописи.
- [ ] Нова база с реален импорт (1164 / 1347 / 7217) за сценарии 11–12; празна/тестова база за останалите.
- [ ] Подготвени файлове: .doc, .docx, снимка, графика, PDF, забранен тип (.exe), файл > 50MB.
- [ ] Включен е записът на писма (стар: пощенска кутия на тестовите адреси; нов: лог/Mailpit).

## 1. Регистрация → потвърждение → вход
- [ ] Форма за регистрация: полета, етикети, задължителност, реда им.
- [ ] Валидации: празни полета, невалиден имейл, вече зает имейл (и с други главни букви), несъвпадащи пароли.
- [ ] Писмо за потвърждение: заглавие, текст, линк, подател.
- [ ] Вход преди потвърждение → същото съобщение/блокиране.
- [ ] Линк за потвърждение: първо отваряне; повторно отваряне.
- [ ] Вход с нов акаунт; изход.
- [ ] Вход със **стар** акаунт (стара SHA1 парола) → влиза; втори вход пак влиза (bcrypt).
- [ ] Грешна парола / несъществуващ имейл – съобщение.
- [ ] Забравена парола: *приет различие* – линк за смяна вместо парола в писмо (L4). Проверка: линкът работи веднъж, изтича.
- [ ] Профил: редакция на полетата, смяна на парола (стара парола изискване, валидации).
- [ ] Меню по роля: автор / рецензент / редактор – същите елементи, същият ред.

## 2. Подаване на ръкопис (автор)
- [ ] Форма: полета (заглавие, abstract, keywords, cover letter, коментар, ръкопис, снимки ≤10, графики ≤5).
- [ ] Валидации: празно заглавие/файл; забранено разширение; прекалено голям файл; повече от 10/5 фигури.
- [ ] Успешно подаване → страница „thank you“/съобщение – текст.
- [ ] Нов код = MAX(код)+1; етикет `JPOP<код>`; id = MAX+1.
- [ ] Имена на файловете: `JPOP<код>`, `_photoN`, `_graphN`.
- [ ] Писмо до автора (SubmissionReceived): получател, заглавие, текст, прикачен `CONSENT_for_AUTHORS.doc`.
- [ ] Писмо до редакторите (SubmissionNotice): получатели (`editor_emails`), текст.
- [ ] Подаване при провал на пощата – ръкописът не се губи.
- [ ] Редактор подава като автор: позволено (прието).

## 3. „My manuscripts“ (автор)
- [ ] Само свои ръкописи; ред `id DESC`; по 5 на страница; пагинация.
- [ ] Колони/полета, дати (формат `дд.мм.гггг`), статуси.
- [ ] Автор НЕ вижда рецензии/препоръки (прието отклонение).
- [ ] Автор А не вижда ръкопис на Б (списък, файл по директен URL, abstract, cover letter).

## 4. Назначаване на рецензент (редактор)
- [ ] Списък „в процес“: ред, колони, цвят (червено при ≥2 „Rejected“).
- [ ] Избор на рецензент за слот 1, 2, 3 – списъкът с рецензенти (само ниво 2), сортиране.
- [ ] Слот само при статус „в процес“.
- [ ] Писмо до рецензента: заглавие (слот 1 vs 2/3 – L9), текст, линкове agree/decline, прикачени ръкопис/Checklist/Instructions (слот 2/3).
- [ ] Дата на покана и срок (+1 месец с преливане, напр. 31.01 → 03.03).
- [ ] „Resend invitation“ – нови линкове, старите вече не работят.
- [ ] Напомняне: текст (редактируем), получател, срок.
- [ ] Редактор, който е подал ръкописа като автор, НЕ може да го обработва (друг редактор).

## 5. Agree / decline (рецензент, от писмо)
- [ ] Линк agree: отваряне → страница; потвърждение (POST) → състояние „confirmed“, дата.
- [ ] Линк decline: слотът се изпразва; писмо до редакторите.
- [ ] Повторно ползване на линк, изтекъл линк (>30 дни), чужд/подправен токен – съобщение.
- [ ] Отваряне на линка от нелогнат потребител работи (и в двете системи).
- [ ] Текстове на страниците и писмата до редакторите.

## 6. Рецензентски екран и качване на рецензия
- [ ] „Manuscripts for review“: само свои слотове, не отказани, `id DESC`, по 5.
- [ ] Връзки: ръкопис, фигури, Checklist, Instructions – работят и се свалят.
- [ ] Качване: рецензиран файл + checklist + препоръка (Minor/Major/Rejected) – всички задължителни.
- [ ] Повторно качване заменя предишното.
- [ ] Имена: `JPOP<код>(reviewerN)`, `(checklist-reviewerN)`.
- [ ] Писмо до автора „Reviewed manuscript“ – текст; **без** прикачен checklist (прието).
- [ ] Писмо до редакторите „Reviewer X uploads file“.
- [ ] Рецензент не вижда чужди ръкописи/файлове (директен URL → 403/404).

## 7. Решение на редактора
- [ ] Editor's Decision: качване на файл → писмо до автора с прикачен файл; текст, заглавие.
- [ ] Повторно качване заменя.
- [ ] „Letters to reviewers“: само към рецензенти с препоръка, с прикачено решение.
- [ ] Директно отхвърляне (DirectReject): статус → rejected, писмо; **без вход → отказ** (в стария – без гард).
- [ ] Всяко действие се вижда в activity log.

## 8. Корекция (автор)
- [ ] Качване на коригиран файл: само собственик; разширения; име `(corrected)`.
- [ ] Коригирани фигури (снимки/графики) – качване, замяна.
- [ ] Прието отклонение: коригирани графики се пазят отделно (`corrected_graph`), не презаписват оригиналите (L3).
- [ ] Писмо „corrected uploaded“ до редакторите.
- [ ] Редакторът вижда коригираните файлове в ръкописа.

## 9. Смяна на статус
- [ ] `mscr_Status`: само редактор; без вход → отказ.
- [ ] Прехода in_progress → rejected → published и обратно (какво е позволено в стария).
- [ ] Няма писмо (както в стария).
- [ ] Ръкописът се премества в правилния списък; броячите на списъците.

## 10. Proof
- [ ] Качване на proof + писмо на редактора → писмо до автора (текст, прикачени файлове).
- [ ] Само редактор; автор вижда/сваля proof само на свой ръкопис.
- [ ] Повторно качване.
- [ ] Няма одобрение от автор (решение).

## 11. Списъци и данни (с реалния импорт)
- [ ] В процес / отхвърлени / публикувани: 7 / 1121 / 216; страница 1 и последната; `id DESC`.
- [ ] 3 ръкописа без автор (34, 342, 343) – не се виждат в списъците (както в стария); присъстват в отчета.
- [ ] Червени препоръки: 451.
- [ ] 10 произволни ръкописа: заглавие, код `JPOP…`, дати, рецензенти, препоръки – 1:1 със стария екран.
- [ ] Рецензент с много назначения (442/420/150 слота): списъкът съвпада с този в стария.
- [ ] Липсващи файлове (210): линк → 404 с разбираемо съобщение, не грешка 500.
- [ ] Дати с `Europe/Sofia…` (19 реда) – как се показват.
- [ ] 2 дублирани имейла – какво става при вход.

## 12. Търсене и помощни страници
- [ ] Search (само редактор): по автор, по заглавие/abstract/cover letter/keywords; резултати, ред, пагинация (15).
- [ ] Abstract / Cover letter: кой ги вижда (редактор, собственик, назначен рецензент – прието ограничение).
- [ ] Instructions (публична), consent документ, помощни файлове на рецензент.
- [ ] Issues – същата празна страница със заглавие.
- [ ] Contacts: форма, валидации, писмо „Message from contact form“, thank-you; карта (прието: OpenStreetMap).
- [ ] `sendemails` – НЕ се мигрира (решение).

## 12а. Users и Logs (само редактор)
- [ ] Менюто „Users“ и „Logs“ се вижда само на редактор (старо: Users, Logos).
- [ ] Users: №, имейл, име, държава/град, дата на регистрация, роля; най-новите първи; по 25 на страница; броячи по роли = филтър (Editors/Reviewers/Authors).
- [ ] Профил на потребител (старо profile_Users) и смяна на роля (старо users_ChangeStatus); смяна на собствената роля е забранена; действието се пише в Logs.
- [ ] Logs: №, потребител, дата, час, IP, действие; най-новите първи; по 50 на страница.
- [ ] Автор и рецензент получават 403 на всичките; без вход → вход.

## 12б. Logs v2 (новото; няма в стария сайт)
- [ ] Вход, грешен вход (запис „Login failed“ без паролата), изход → редове в категория Sign-in; бърз изглед „Failed logins“.
- [ ] Отваряне на ръкопис/файл/abstract → категория Views (един ред за една и съща страница в рамките на минута); самият екран Logs не се записва.
- [ ] Успешно качване (ръкопис, рецензия, proof…) → Uploads с име и размер в „details“; недопустим файл (напр. .exe) → ред „Upload refused“ с причина (бърз изглед „Refused uploads“).
- [ ] Достъп отказан (автор отваря /editor/users) → Security, HTTP 403.
- [ ] Писмата → категория Mail (получател и тема); грешка в приложението → Errors (червен ред).
- [ ] Филтри (категория, ниво, потребител, ръкопис, период, текст), „[ms N]“ филтрира по ръкопис, Export CSV на филтрирания изглед.
- [ ] `php artisan jpop:logs:prune --dry-run` показва броя за изтриване по категории; старите (legacy) редове не се пипат.

## 13. Достъп (матрица от плана §4)
- [ ] Без вход: всяка защитена страница → пренасочване към вход; публични – достъпни.
- [ ] Автор: няма достъп до редакторски и рецензентски екрани.
- [ ] Рецензент: няма достъп до редакторски и авторски екрани.
- [ ] Старите URL към файлове (`download/*.php`) не работят (прието).
- [ ] `mscr_Published`: само влезли потребители.

## 14. Писма (обобщено)
За всяко от ~20 писма: [ ] получател [ ] заглавие [ ] текст [ ] прикачени [ ] линкове [ ] кодиране (кирилица, специални знаци) [ ] подател/Reply-To.
- [ ] Писма през опашката: излизат до минута от cron.
- [ ] Редакторските получатели от `editor_emails`; при празно – всички редактори.

## 15. Външен вид и устойчивост
- [ ] Ширина на мобилен/таблет; навигация.
- [ ] Кирилица в имена, заглавия, файлове с интервали и скоби.
- [ ] Часова зона на датите.
- [ ] Двойно натискане на „Submit“ – няма дубликат.
- [ ] Сесия: изтичане, вход от нов браузър.

## Приети отклонения (не са дефекти)
| Област | Отклонение |
|---|---|
| Забравена парола | линк за смяна вместо парола в явен вид (L4) |
| Регистрация | throttle вместо captcha |
| Достъп до файлове | само през `/files/{id}`, по роля; старите URL не се пазят (L1) |
| Корекция | коригирани графики не презаписват оригиналите (L3) |
| Рецензии | авторът не вижда рецензии/препоръки; писмото до автора без checklist |
| Линк на рецензент | еднократен, 30 дни, GET само показва, действието е POST |
| Редактори | редактор може да подава, но не и да обработва собствен ръкопис |
| Абстракт/cover letter | само редактор, собственик, назначен рецензент |
| Contacts | throttle + honeypot, OpenStreetMap вместо Google Maps |
| Заглавия на писма (L9) | пазени както са – в backlog |
| sendemails | не се мигрира |
| Logs | няма „Empty logos“ (изтриване на журнала с един клик); журналът се пази |
| Users | няма отделна страница с броячи 1/2/3 на рецензент (`users_Index_Lavel_next`); смяна на собствената роля е забранена |
| Странициране | всички списъци са странирани с номера на страници (преди – само Prev/Next) |

## Критерий за край на етапа
Всички редове са `[x]` или `[~]` с вписана разлика; няма отворени `[!]`; журналът е ревюиран; репетицията по `docs/04-cutover.md` е минала.
